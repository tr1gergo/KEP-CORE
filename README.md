# Kidney Exchange Core Analyses

This repository contains the experimental framework used to evaluate the required altruist use for core-stable kidney exchange allocations. Stability claims in the main study are explicitly capped at coalitions of at most nine organizations.

## Main files

- `KEP_functions.py` implements compatibility graphs, cycle enumeration, lexicographic allocation, exact joint blocking-coalition separation, sequential TU-core donor augmentation, and secondary strong/weak search heuristics.
- `management_science_simulations.py` contains the reproducible and resumable experiment driver.
- `paper_simulations_maxcoal**.ipynb` configures, launches, resumes, and analyzes the paper study with different coalition caps.
- `instance_analysis.py` parses the XML instances and donor/recipient metadata.
- `instances/` and `instances_large/` contain the source XML pools.
- `results/management_science_revised/` is created by the main experiment and contains its manifest, append-only raw checkpoint, CSV export, and summary tables. The distinct directory prevents earlier exploratory artifacts from being mixed into the revised study.

## Experimental design

The default `StudyConfig` uses:

- 30 independently generated 1,000-pair base pools selected by a fixed seed and recorded with SHA-256 hashes;
- induced pools of 100, 200, and 500 pairs;
- 5, 10, 20, and 30 organizations;
- cycle caps of 2 and 3;
- two independent organizational partitions per graph;
- three random donor permutations, evaluated only when the donor-free computation does not settle the outcome;
- a coalition-size cap of four.

The randomization is staged. A patient sample depends only on base pool and pool size. A partition additionally depends on organization count and partition replication, but is shared across cycle caps. Donor permutations are shared across algorithms and cycle caps for the same market.

## Algorithms and interpretation

`core_tu_simple` uses valid aggregate TU coalition constraints generated by a single exact separation MIP. It solves without altruists first and introduces donors one at a time only after the current master is certified infeasible. It records donors introduced separately from donors selected in the final exchange.

`lexicographic_core_search` checks the selected allocation with an exact weak-blocking-coalition separator. This certifies stability of that allocation; it is not a weak-core existence algorithm.

TU-core stability implies strong-core and weak-core stability for the same allocation. When TU finds a donor-free allocation, the experiment driver records exact zero-donor strong/weak feasibility instead of rerunning two redundant searches. When TU needs donors, the optional strong/weak aggregate-cut heuristics still run because they may find a donor-free allocation. A stable allocation found by those heuristics is valid, but failure does not certify core emptiness and their donor counts are not minima.

Every solver result is classified as certified, infeasible, timed out, or otherwise uncertified. Uncertified rows are never converted into zero-donor or stability observations.

## Running the study

1. Install Python 3.10+, NumPy, pandas, matplotlib, NetworkX, PuLP, and a licensed Gurobi installation. CBC can be used for small tests.
2. Open `paper_simulations_maxcoal**.ipynb` with the project environment.
3. Run the pilot cell first and inspect its runtime table.
4. Set `RUN_FULL_STUDY = True` to start or resume the main experiment.

The driver appends each completed algorithm/order result to `raw_results.jsonl`. Re-running the same configuration resumes from that file. A changed design must use a new output directory so that its manifest cannot be mixed with an earlier run.

## Tests

Run:

```powershell
.\.venv-ms\Scripts\python.exe -m unittest discover -s tests -v
```

The tests use CBC and cover exact weak/strong/TU separation, sequential donor introduction, donor accounting, and reproducible donor permutations.
